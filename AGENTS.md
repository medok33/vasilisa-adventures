# Правила работы с проектом

Эти правила обязательны для любого нового чата или разработчика.

## Сначала синхронизация

Перед изменениями выполнить:

```bash
git status --short
git log --oneline -20
```

Затем прочитать `README.md`, `docs/PROJECT_STATE.md`, `CHANGELOG.md` и
`vds/README.md`, а также `docs/ACTIVE_IMPLEMENTATION_PLAN.md`. Не начинать
работу заново, если нужная функция уже существует.

## Единый источник истины

- Ветка выпуска: `main`.
- Канонический исходный код: публичный GitHub-репозиторий
  `https://github.com/medok33/vasilisa-adventures`.
- Внутренний репозиторий Sites не использовать для новых серверных обновлений.
- Репозиторий публичный: запрещено коммитить токены, пароли, ключи, cookies,
  приватные файлы, дампы данных и содержимое `.env`.
- Секретные значения допускаются только в серверных переменных окружения.
- Перед каждым push проверить staged diff и выполнить поиск потенциальных
  секретов.
- Каждый законченный пакет правок оформляется отдельным понятным коммитом.
- Активный статус, критерии приёмки и подробная передача следующему агенту
  обязательно фиксируются в `docs/ACTIVE_IMPLEMENTATION_PLAN.md`.
- Вместе с кодом обновляются `docs/PROJECT_STATE.md` и `CHANGELOG.md`.
- Перед началом новой работы всегда подтягивается актуальная `main`.
- Запрещены force-push, переписывание опубликованной истории и удаление
  пользовательских данных.

## Передача между аккаунтами

- Новый чат может работать из другого ChatGPT-аккаунта через GitHub, если его
  подключённый GitHub-аккаунт имеет право записи в репозиторий.
- История дней, подписи и прогресс ребёнка не хранятся в GitHub: они остаются
  только в постоянном томе VDS.
- Доступ к Selectel и серверным переменным окружения не передаётся вместе с
  кодом. Не просить и не вставлять пароли, токены или API-ключи в чат.

## Жёсткие ограничения

- Не трогать Weight App, его контейнеры, каталог, базу, сеть и порт `3000`.
- Проект Василисы живёт отдельно в `/opt/vasilisa-adventures/source`.
- Контейнер приложения слушает `127.0.0.1:3100`.
- Публичные `80/443` обслуживает отдельный Caddy проекта Василисы.
- Данные прогресса находятся в постоянном томе
  `vasilisa-adventures-data`; при обновлениях его не пересоздавать и не удалять.
- Уведомления папе через VK/MAX пока не настраивать: это отдельная будущая
  задача, требующая подключения официального канала/бота.
- Номер телефона и ссылка VK являются осознанно публичными контактами,
  отображаемыми на самом сайте. Другие персональные данные не добавлять без
  отдельного подтверждения владельца.

## Эмоциональная безопасность ребёнка

- Ошибка или незавершённое задание не должны выглядеть как наказание,
  разочарование взрослого или повод испытывать вину.
- Не использовать в детском интерфейсе формулировки «неверно», «ошибка»,
  «не справилась», «потеряла», «не заслужила» и похожие оценки ребёнка.
- Поддерживать самостоятельную повторную попытку: «можно попробовать ещё»,
  «выбери другой вариант», «давай посмотрим ещё раз».
- Сначала показывать уже достигнутый результат. Дополнительную награду
  объяснять как необязательный бонус, а не как отнятую или недополученную часть.
- Неправильный учебный ответ не уменьшает уже заработанную награду и не
  отменяет выполненное полезное действие.
- Тон интерфейса должен оценивать способ решения или следующий шаг, а не
  личность, способности или моральные качества ребёнка.

## Бережный контроль чтения

- В одном дневном фрагменте показывать не более одного вопроса и только при
  пересечении заранее заданной смысловой контрольной точки книги.
- Не проверять мелкие факты подряд. Для каждой книги хранить короткий чек-лист
  важных сюжетных причин, поступков героев и главных мыслей.
- Вопрос можно пропустить: чтение и основные звёзды уже сохранены, а ответ
  открывает только дополнительную звезду.
- После последней страницы предложить Василисе свободную книжную заметку о
  понимании и впечатлениях. Её текст нельзя оценивать или сравнивать с образцом.
- За факт завершения книги и сохранения заметки один раз начисляется отдельный
  папин персональный бонус `10 ⭐`; содержание и объём текста на бонус не влияют.

## Проверка и публикация

1. Внести изменения локально.
2. Выполнить производственную сборку.
3. Проверить diff и обновить журнал проекта.
4. Создать коммит и отправить его в `main`.
5. На VDS обновить только этот проект.
6. Пересобрать только сервис `app`:

```bash
cd /opt/vasilisa-adventures/source
git pull --ff-only origin main
docker compose -f vds/compose.yaml up -d --build app
docker compose -f vds/compose.yaml ps
docker compose ls
```

После публикации проверить `https://nectarra.ru/`, состояние контейнера
`vasilisa-adventures-app-1` и наличие пяти работающих контейнеров
`weight-app-staging`.

## Передача работы следующему чату

Последний исполнитель обязан оставить в `docs/PROJECT_STATE.md`:

- установленный commit SHA;
- что именно изменено;
- что проверено;
- что осталось сделать;
- известные ограничения или риски.

Нельзя сообщать об успешной публикации без проверки основного домена и
состояния контейнеров.
