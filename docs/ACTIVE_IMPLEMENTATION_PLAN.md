# Активный план развития «Приключений Василисы»

Дата создания: 1 сентября 2026 года.

Этот файл — единая рабочая точка передачи проекта между агентами. Любой
исполнитель обязан сначала прочитать `AGENTS.md`, затем этот файл, проверить
фактический `main`, production и данные, и только после этого начинать работу.

## 1. Правила ведения плана

Допустимые статусы:

- `NOT_STARTED` — работа не начиналась;
- `IN_PROGRESS` — один агент ведёт пакет прямо сейчас;
- `BLOCKED` — продолжение невозможно без решения владельца или внешних данных;
- `REVIEW` — код готов, но не прошёл все проверки или не опубликован;
- `DONE` — выполнены критерии приёмки, проверки, commit и production-проверка;
- `DEFERRED` — владелец осознанно отложил пакет.

Одновременно статус `IN_PROGRESS` может иметь только один крупный пакет.
Перед началом агент указывает дату, своё обозначение и базовый commit. После
завершения он обязан в том же файле:

1. сменить статус;
2. перечислить фактические изменения;
3. записать commit SHA;
4. перечислить выполненные тесты и их результат;
5. указать, опубликована ли правка на production;
6. зафиксировать известные риски и следующий конкретный шаг;
7. добавить строку в журнал выполнения в конце файла.

Запрещено ставить `DONE`, если отсутствует хотя бы один критерий приёмки.
Запрещено записывать сюда логины, пароли, ключи, cookies, токены, персональные
данные ребёнка, содержимое БД и серверного `.env`.

## 3. Очередь пакетов

### R1 — корректный сценарий чтения

**Статус:** `NOT_STARTED`  
**Приоритет:** критический  
**Следующий рекомендуемый пакет:** да

Проблемы:

- вопрос определяется по уже сохранённой странице, а не по текущему диапазону;
- поздравление появляется раньше вопроса;
- первый вопрос «Волшебника» открывается только после страницы 40, поэтому
  диапазон 5–30 остаётся без вопроса;
- правильный ответ прошлых дней может влиять на награду нового дня;
- экран чтения перегружен крупными блоками и техническими данными.

Работы:

- разделить сохранение страниц, текущий вопрос и финальное поздравление;
- определять вопрос по фактически прочитанному сегодня диапазону;
- хранить связь `день → книга → диапазон → вопрос → ответ`;
- начислять третью звезду только за правильный текущий вопрос;
- не отменять факт чтения при неправильном ответе;
- добавить проверенные вопросы для всех разумных фрагментов книг;
- показывать обычно один вопрос на факт и один на понимание, без спойлеров;
- упростить мобильный экран: компактный прогресс, поля страниц, небольшие
  переключатели времени, вопрос и одна основная последовательность действий;
- спрятать ISBN и технические данные в раскрываемый блок «О книге».

Критерии приёмки:

- диапазон 5–30 первой книги открывает релевантный вопрос;
- страницы сохраняются даже при неверном ответе;
- неверный ответ не даёт третью звезду;
- верный ответ текущего дня даёт ровно одну дополнительную звезду;
- ответ прошлого дня не даёт звезду сегодня;
- поздравление появляется один раз после завершения текущего сценария;
- тесты покрывают граничные страницы, повторный ответ и переход к новой книге;
- экран проверен на мобильной ширине без перекрытия нижней навигацией.

### R2 — нормальные подсказки и их аналитика

**Статус:** `NOT_STARTED`  
**Приоритет:** высокий  
**Зависимость:** желательно выполнить вместе с R1 или сразу после него

Работы:

- отделить визуальное состояние `подсказка раскрыта` от постоянного факта
  `подсказка использована`;
- повторное нажатие и кнопка закрытия должны скрывать подсказку;
- скрытие не должно стирать факт использования из аналитики;
- показывать подсказку после первой ошибки либо осознанного запроса;
- сделать компактную карточку, не раздвигающую строку задания;
- заменить универсальные английские подсказки на подсказки по навыку;
- подсказка объясняет первый шаг или правило, но не сообщает готовый ответ.

Критерии приёмки:

- подсказка открывается и закрывается без потери ответа;
- `hint_used` остаётся истинным после закрытия;
- использование подсказки учитывается адаптивным алгоритмом;
- подсказки Math и English содержательно различаются;
- мобильная и desktop-вёрстка не ломаются.

### R3 — генератор математики v2

**Статус:** `NOT_STARTED`  
**Приоритет:** высокий  
**Зависимость:** R2

Причина: текущий выбор навыков способен заполнить четыре из пяти позиций
одинаковыми уравнениями или другим одним навыком.

Работы:

- ежедневно выдавать пять задач минимум по трём разным навыкам;
- не больше двух заданий одного навыка за день;
- роли дня: разминка, школьная тема, задача из жизни, логика/поиск ошибки,
  небольшой вызов;
- добавить шаблоны по времени, деньгам, измерениям, геометрии, числовым
  последовательностям, задачам в два действия и выбору операции;
- сохранять независимый уровень каждого навыка;
- сохранять закрепление слабых тем через 2/4/7 дней;
- исключать точные повторы и одинаковую композицию соседних дней;
- оформить задания как элементы сюжета, а не как одинаковые строки теста.

Критерии приёмки:

- симуляция 30 дней не содержит точных повторов в защитном окне;
- каждый день содержит минимум три навыка и минимум четыре формата;
- не больше двух заданий одного навыка;
- семидневная адаптация повышает только подтверждённый навык;
- одна ошибка не понижает уровень;
- все ответы и попытки продолжают сохраняться.

**Приоритет:** высокий

Работы:

- не добавлять картинку, если она не помогает понять задание;
- расширить словарь и грамматические шаблоны уровня третьего класса;
- добавить разные механики ответа, сохранив доступность на телефоне;
- улучшить неправильные варианты ответа и подсказки по навыкам.

Критерии приёмки:

- нет серии однотипных карточек с emoji;

- симуляция 30 дней проходит защиту от повторов;
- spelling, grammar, порядок слов и чтение независимо попадают в аналитику.
